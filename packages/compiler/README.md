# @mcpify/compiler: Recording → draft Tool (Semantic Step Contracts)

```bash
pnpm --filter @mcpify/compiler compile --recording <file|id> [--out file] [--validate] [--site-id <id>] [--no-llm]
```
Loads the recording (file path, an id in `recordings/`, or `GET /recordings/:id`), compiles it, writes the draft (status `draft`)
to `.data/tools/drafts/<site>.<name>.json` (+ `--out`), and `POST /tools` when the API is up and the site is known.
Then: `pnpm --filter @mcpify/mcp-server approve <draft.json>`.

```ts
import { compile, validateDraft } from '@mcpify/compiler';
const draft = await compile(recording, { loadSnapshot?, llm?, siteId?, siteName? });
draft.validation = await validateDraft(draft);   // optional dry run on the live site
```

## Pass 1: deterministic (always)
- **Steps**: the first page load (and any navigation not caused by a click) → `navigate`; text → `fill`; `<select>` → `select`;
  checkbox → `check`; file → `upload`; masked (`•••`) field → `userInput` (`auth`, `sensitive`, `repair: human`, param `otp`/`captcha`/...);
  button/link clicks → `click`; a `submit` from Enter → click on that form's submit button. Final `extract` of a generated reference on
  the last page (`SSP-\d{4}-\d{6}`-like tokens or values labelled "Application/Reference ... ID/No"); the regex is derived from the value.
- **Risk** (01-CONTRACTS §15): Next/Continue buttons that lead to another page of the same form (still has fields) → `fill`;
  text matching `submit|send|pay|confirm|save|apply|register|book|sign in/up|log in` and the **last** button → `commit`; links → `read`;
  other submit buttons → `commit`. `commit`/`auth` → `repair: "human"`, else `auto`.
- **Locators** (`candidateLocators`): testid > id (skips auto-generated ids) > name > label > role+name > text (buttons/links) > near > css > xpath.
  Each candidate is **verified in the step's DOM snapshot** (loaded headless with JavaScript and network off) with the engine's own
  resolver (`@mcpify/engine/in-page`): it must match exactly one visible element **and** that element must be the recorded one.
  The first 2–5 verified ones are kept. Without a snapshot the draft still compiles with unverified locators and a warning.
- **Conditions**: `pre = visible`; fill/select/check `post = valueEquals + noErrorNear`; clicks `post = urlMatches(next page)`, or
  `textPresent(new text)` when the URL did not change (e.g. "OTP has been sent ..."); navigate `post = urlMatches + textPresent(page heading)`.
- **Params / inputSchema**: snake_case from the label (`Mobile Number` → `mobile`, declarations → `declaration`), `title` = label,
  `enum` = select option labels (placeholders dropped), `date`/`email`/`integer`/`boolean` from the field type and value, file params
  default to the recorded file name. OTP/CAPTCHA are not inputs. `draft.examples` holds the recorded non-sensitive values.

## Pass 2: LLM (only when `llmAvailable()`)
One `parseJson` call per recording (`LlmToolSchema`, the R4 schema) with steps, labels, redacted example values (`•••` for sensitive,
`redactForLlm` for the rest) and short redacted DOM excerpts. Merged safely: names, titles, intents, description; risk can only go **up**;
`userInput` stays `auth`. Any LLM error keeps the rules-only draft with a warning.

## Validation run (`--validate`)
Runs the draft with the engine + Playwright (headless) in **dry run** with `draft.examples` (sensitive params excluded). Commit steps are
blocked by the engine; for sites that are not owner-mode demo portals in `fixtures/sites.json` the network guard is on too.
Result in `draft.validation`.

## Exported building blocks (reusable by repair)
`candidateLocators`, `pickLocators`, `looksAutoGenerated`, `roleOf`, `SnapshotDom` (`verify`, `facts`, `outputs`, `formButton`, `excerpt`),
`classifyClick`, `paramNameFromLabel`, `sensitiveParamName`, `patternFromValue`, `buildInputSchema`, `planSteps`, `mergeLlm`, `draftToTool`.

## Tests
`pnpm --filter @mcpify/compiler test`:
- `e2e.test.ts`: records a scripted full Portal 1 application with the programmatic recorder, compiles rules-only, checks the golden
  step/risk sequence and that every locator resolves uniquely to its element in its snapshot, then **runs the compiled tool end to end**
  on a fresh Portal 1 (confirmations approved, OTP/CAPTCHA from `/__lab`) → `succeeded` with `application_id`; plus the dry-run validation.
- `unit.test.ts`: locator synthesis, naming, risk rules, and compiling the saved fixture `tests/fixtures/portal1.*.json`.
- `llm.test.ts`: the LLM pass with a mocked Claude (`setClaudeForTests`).
Regenerate the fixture: `UPDATE_FIXTURES=1 pnpm --filter @mcpify/compiler exec vitest run tests/e2e.test.ts`.
